# kolesa_control

ROS 2 нода дифференциального управления гусеничным роботом через два
контроллера **FS75100** (на базе VESC) по UART, с чтением телеметрии.

- FS75100 №1 (uart4) → по умолчанию **левая** гусеница
- FS75100 №2 (uart5) → по умолчанию **правая** гусеница

## Интерфейс

Подписки:
- `/cmd_vel` (`geometry_msgs/Twist`) — команда скорости. `linear.x` — вперёд,
  `angular.z` — поворот (против часовой стрелки, REP-103).

Публикации:
- `/joint_states` (`sensor_msgs/JointState`) — положение и скорость гусениц,
  рассчитанные из телеметрии VESC. Это то, что потребляет ваш узел
  `/robot_odom` для одометрии.
- `/kolesa/diagnostics` (`diagnostic_msgs/DiagnosticArray`) — напряжение, токи,
  температуры, скважность, обороты и код неисправности по каждому контроллеру.

Управление по скорости реализовано через **скважность (duty cycle,
`COMM_SET_DUTY`)**, а не через обороты VESC. Это управление РАЗОМКНУТОЕ:
узел переводит `cmd_vel` в долю питающего напряжения на моторе
(`duty_min`..`duty_max`), а не в целевые обороты — VESC сама скорость не
регулирует. Одна и та же скважность даёт разную реальную скорость в
зависимости от нагрузки, уклона и напряжения батареи. Команды повторяются
с частотой `control_rate` и служат «keep-alive»: если `/cmd_vel` пропадает
дольше `cmd_timeout`, гусеницы останавливаются (скважность 0). Это
дублируется штатной защитой VESC по таймауту.

Одометрия (пройденное расстояние и скорость) считается в узле по
**абсолютному счётчику тахометра VESC**, пересчитанному в обороты выходного
вала: `tacho_counts_per_revolution` (тиков на один оборот) и
`distance_per_revolution` (метров пройдено за один оборот). Второе значение
нужно определить экспериментально — см. «Калибровка одометрии» ниже. eRPM/
скважность из телеметрии VESC используются только для диагностики, на
расчёт расстояния и скорости не влияют.

## Сборка

Положите пакет в `src` вашего рабочего пространства:

```
cd ~/ros2_ws
colcon build --packages-select kolesa_control
source install/setup.bash
```

Зависимость `pyserial` ставится через rosdep (`python3-serial`) или вручную:
`pip install pyserial`.

## Запуск

```
ros2 launch kolesa_control kolesa_control.launch.py
```

или напрямую с параметрами:

```
ros2 run kolesa_control kolesa_control --ros-args \
  -p left_port:=/dev/ttyTHS4 -p right_port:=/dev/ttyTHS5 \
  -p wheel_radius:=0.10 -p wheel_separation:=0.50 -p pole_pairs:=7
```

## Параметры

| Параметр | По умолч. | Описание |
|---|---|---|
| `left_port` | `/dev/ttyTHS4` | устройство левого контроллера |
| `right_port` | `/dev/ttyTHS5` | устройство правого контроллера |
| `baud` | `115200` | скорость UART |
| `wheel_radius` | `0.10` | эффективный радиус ведущей звёздочки, м (также используется для грубой оценки одометрии по умолчанию) |
| `wheel_separation` | `0.50` | колея (между гусеницами), м |
| `gear_ratio` | `1.0` | оборотов двигателя на оборот выходного вала (редуктор) |
| `pole_pairs` | `7` | число пар полюсов двигателя (для eRPM и оценки `tacho_counts_per_revolution` по умолчанию) |
| `tacho_counts_per_revolution` | `0.0` | тиков абс. тахометра VESC на один оборот выходного вала. `0.0` = автооценка `3 * pole_pairs * gear_ratio` при старте (см. лог узла) — **ОБЯЗАТЕЛЬНО откалибруйте**, см. ниже |
| `distance_per_revolution` | `0.0` | пройденное расстояние (м) за один оборот выходного вала. `0.0` = грубая автооценка `2*pi*wheel_radius` — **ЭКСПЕРИМЕНТАЛЬНАЯ калибровка обязательна**, см. ниже |
| `odometry_scale` | `1.0` | итоговый поправочный коэффициент одометрии (тонкая подстройка после калибровки) |
| `invert_left` | `false` | инверсия направления левого |
| `invert_right` | `true` | инверсия направления правого (зеркало) |
| `duty_min` | `0.05` | минимальная ненулевая скважность VESC (0..1), чтобы преодолеть трение покоя |
| `duty_max` | `0.5` | максимальная скважность VESC (0..1) — ограничение по безопасности/напряжению |
| `control_rate` | `50.0` | Гц, частота отправки команд |
| `telemetry_rate` | `20.0` | Гц, частота опроса/публикации |
| `cmd_timeout` | `0.5` | с, стоп при отсутствии `/cmd_vel` |
| `publish_joint_states` | `true` | публиковать `/joint_states` |
| `left_wheel_joint` | `left_track_joint` | имя сустава |
| `right_wheel_joint` | `right_track_joint` | имя сустава |
| `publish_diagnostics` | `true` | публиковать диагностику |

## Имена UART-устройств

«uart4 / uart5» в системе видны как файлы устройств, имя зависит от платы:

- **Jetson (Orin/Xavier):** `/dev/ttyTHS4`, `/dev/ttyTHS5` (значения по умолчанию).
- **Raspberry Pi:** `/dev/ttyAMA4`, `/dev/ttyAMA5` (или `/dev/serial0`).
- **Обычный ПК / USB-UART:** `/dev/ttyUSB0`, `/dev/ttyUSB1`.

Посмотреть доступные порты: `ls -l /dev/serial/by-path/` или `dmesg | grep tty`.
Чтобы не путать порты местами, удобно прописать стабильные имена через правила
udev (`/dev/fs75_left`, `/dev/fs75_right`) и указать их в параметрах.

Дайте пользователю доступ к портам: `sudo usermod -a -G dialout $USER`
(перелогиниться после этого).

## Настройка под свой робот

1. Замерьте `wheel_radius` и `wheel_separation`, узнайте `pole_pairs`
   двигателя и `gear_ratio` редуктора.
2. На малой скважности (`duty_min` небольшой, например `0.05`) подайте
   `linear.x` вперёд и проверьте, что **обе** гусеницы крутятся вперёд. Если
   одна назад — поставьте соответствующий `invert_*`.
3. Проверьте поворот: при `angular.z > 0` робот должен поворачивать влево
   (левая гусеница медленнее/назад). Если наоборот — порты перепутаны,
   поменяйте `left_port`/`right_port`.
4. Подберите `duty_min` (минимум, при котором гусеницы реально трогаются с
   места) и `duty_max` (безопасный потолок скорости для вашего робота и
   батареи) — методом проб на приподнятом роботе.
5. Обязательно выполните калибровку одометрии (см. ниже) — без неё
   `/odom`/`/joint_states` будут использовать только грубую оценку по
   номинальному радиусу колеса.
6. Сверьте знак скорости в `/joint_states` с реальным движением — при
   неверном знаке одометрия будет «уезжать».

## Калибровка одометрии

Одометрия считается по формуле `distance = revolutions × distance_per_revolution`,
где `revolutions = delta(abs tachometer) / tacho_counts_per_revolution`. Оба
коэффициента нужно уточнить экспериментально на реальном роботе (значения
по умолчанию — только грубая оценка, годится для первого включения, но не
для точной навигации):

1. Поставьте робота на открытую ровную поверхность, запустите узел, откройте
   `ros2 topic echo /kolesa/diagnostics` (поле `total_abs_counts` для каждой
   гусеницы).
2. Запишите `total_abs_counts` ДО начала заезда для обеих гусениц.
3. Проедьте робота вперёд по прямой на измеримое рулеткой/маркерами
   расстояние `D` (метры) — чем длиннее заезд, тем точнее калибровка
   (рекомендуется от 5 м).
4. Запишите `total_abs_counts` ПОСЛЕ заезда, посчитайте разницу
   `delta_counts` для каждой гусеницы отдельно (обычно должны совпадать
   между левой и правой гусеницей с точностью до пробуксовки).
5. Если `tacho_counts_per_revolution` уже известен точно (иначе оставьте
   автооценку по умолчанию и уточняйте позже) — число оборотов
   `R = delta_counts / tacho_counts_per_revolution`.
6. `distance_per_revolution = D / R`. Впишите полученное число в параметр
   `distance_per_revolution` (в launch-файле, `ros2 param set` или через
   вкладку «Настройка» десктоп-приложения).
7. Проверьте: проедьте ещё раз то же измеримое расстояние и сравните
   показания `/odom`/накопленную `distance` в диагностике с реальным
   пройденным путём. При необходимости точной подстройки используйте
   `odometry_scale` (например, если одометрия систематически завышает путь
   на 3%, поставьте `odometry_scale: 0.97`).

## Проверка

```
# подать команду вперёд (в диапазоне duty_min..duty_max)
ros2 topic pub -r 10 /cmd_vel geometry_msgs/Twist "{linear: {x: 0.2}}"

# смотреть телеметрию (в т.ч. duty_target/duty_measured, total_abs_counts)
ros2 topic echo /kolesa/diagnostics

# смотреть состояние колёс
ros2 topic echo /joint_states
```

## Безопасность

Команды запускают двигатели. Перед испытаниями вывесите робот так, чтобы
гусеницы не касались земли, освободите зону вращения. Узел сам останавливает
двигатели при пропадании `/cmd_vel`, при завершении работы и при потере связи
с контроллером.
