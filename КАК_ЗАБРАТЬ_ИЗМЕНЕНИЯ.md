# Как забрать изменения на робота — пошагово для новичка

Этот файл отвечает на один вопрос: **«код написан, но он где-то не у меня —
как перенести его на Raspberry Pi и запустить?»**

---

## 1. Где физически лежит код

Есть три разных места, и их важно не путать.

| Место | Что это | Адрес |
|---|---|---|
| **GitHub** | Хранилище в интернете. Главный источник правды | `github.com/Kos220v/ros2_ws` |
| **Raspberry Pi** | Копия репозитория на самом роботе | `~/ros2_ws` на Pi |
| **Ваш компьютер** | Ещё одна копия, если вы её делали | `~/ros2_ws` на ПК |

Новый код сейчас лежит **на GitHub**. На робота он сам не попадёт —
его нужно скачать командой `git`.

---

## 2. Что такое ветка и почему `arena/01a01e47-ros2-ws`

Ветка — это **параллельная версия проекта**.

Представьте тетрадь с черновиком. Вы не стираете написанное, а заводите
новый лист и переписываете начисто. Если получилось хорошо — вклеиваете
лист в чистовик. Если нет — выбрасываете, а чистовик остался цел.

- `main` — ваш **чистовик**. Тот код, что работал до сих пор. Он не тронут.
- `arena/01a01e47-ros2-ws` — **новый лист** с автономной навигацией.

Смысл в том, что если новый код вам не подойдёт, вы одной командой
возвращаетесь на `main`, и робот работает как раньше. Ничего не потеряно.

Посмотреть новую ветку в браузере (можно прямо сейчас, ничего не устанавливая):

```
https://github.com/Kos220v/ros2_ws/tree/arena/01a01e47-ros2-ws
```

Посмотреть **только различия** между старым и новым кодом:

```
https://github.com/Kos220v/ros2_ws/compare/main...arena/01a01e47-ros2-ws
```

## 3. Забираем код на Raspberry Pi

Подключитесь к роботу по SSH и выполняйте команды по одной.

### Шаг 1. Перейти в папку проекта

```bash
cd ~/ros2_ws
```

Проверьте, что вы в нужном месте — команда должна показать `src`:

```bash
ls
```

### Шаг 2. Сохранить свои несохранённые правки

Если вы что-то правили на Pi руками, эти правки могут помешать.
Посмотрите, есть ли они:

```bash
git status
```

- Написано `nothing to commit, working tree clean` → всё чисто, идите дальше.
- Перечислены файлы → сначала сохраните их, иначе потеряете:

```bash
git stash
```

(Эта команда убирает ваши правки «в карман». Вернуть потом: `git stash pop`.)

### Шаг 3. Скачать новую ветку с GitHub

```bash
git fetch origin
```

Команда только скачивает данные, но **ничего не меняет** в рабочих файлах.
Она безопасна, её можно выполнять сколько угодно раз.

### Шаг 4. Переключиться на новую ветку

```bash
git checkout arena/01a01e47-ros2-ws
```

Вот теперь файлы на диске изменились. Проверьте, что появился новый пакет:

```bash
ls src/robot_navigation
```

Должно быть: `config  launch  package.xml  README.md  resource  robot_navigation  setup.cfg  setup.py`

### Шаг 5. Установить недостающие программы

Новый код использует готовые пакеты ROS, которых у вас, скорее всего, ещё нет:

```bash
sudo apt update
sudo apt install -y \
  ros-jazzy-robot-localization \
  ros-jazzy-imu-filter-madgwick \
  ros-jazzy-nmea-navsat-driver \
  ros-jazzy-navigation2 \
  ros-jazzy-nav2-bringup \
  ros-jazzy-nav2-regulated-pure-pursuit-controller \
  ros-jazzy-nav2-simple-commander
```

Это займёт несколько минут и потребует интернета на роботе.

### Шаг 6. Собрать проект

```bash
cd ~/ros2_ws
./rebuild.sh
source install/setup.bash
```

`rebuild.sh` полностью очищает прошлые результаты сборки и собирает проект
заново. Не собирайте вперемешку `colcon build` и `colcon build
--symlink-install`: это ломает метаданные Python-пакетов, и узлы падают при
запуске с ошибкой `PackageNotFoundError`, хотя сборка выглядела успешной.

Команда `source` нужна **в каждом новом терминале**. Чтобы не повторять
её вручную, добавьте один раз:

```bash
echo "source ~/ros2_ws/install/setup.bash" >> ~/.bashrc
```

### Шаг 7. Убедиться, что новые узлы видны

```bash
ros2 pkg executables robot_navigation
```

Ожидаемый вывод:

```
robot_navigation gps_waypoint_commander
robot_navigation gps_waypoint_logger
robot_navigation mag_declination_node
robot_navigation nav_preflight_check
```

Если список пустой — сборка не прошла, смотрите ошибки из шага 6.

**После этого переходите к `src/robot_navigation/README.md`** — там
описана настройка робота начиная с калибровки магнитометра.

## 4. Как вернуться назад, если что-то пошло не так

Это главное, ради чего нужны ветки. Возврат к старому рабочему коду:

```bash
cd ~/ros2_ws
git checkout main
colcon build --symlink-install
source install/setup.bash
```

Всё. Робот снова работает как до изменений. Новая ветка при этом никуда
не делась — вернуться к ней можно в любой момент той же командой
`git checkout arena/01a01e47-ros2-ws`.

Узнать, на какой ветке вы сейчас находитесь:

```bash
git branch
```

Звёздочка `*` стоит напротив текущей.

## 5. Если новый код вас устроил

Когда робот успешно проехал маршрут и вы решили, что новая версия —
основная, её нужно «вклеить в чистовик», то есть слить в `main`.

**Способ 1 — через сайт GitHub (рекомендую новичку, там всё видно глазами):**

1. Откройте: `https://github.com/Kos220v/ros2_ws/compare/main...arena/01a01e47-ros2-ws`
2. Нажмите **Create pull request**, затем ещё раз **Create pull request**.
3. Пролистайте вкладку **Files changed** — увидите все изменения построчно.
4. Нажмите **Merge pull request** → **Confirm merge**.

**Способ 2 — командами на Pi:**

```bash
cd ~/ros2_ws
git checkout main
git merge arena/01a01e47-ros2-ws
git push origin main
```

Не торопитесь с этим шагом. Пока изменения живут в отдельной ветке,
ваш рабочий код в полной безопасности.

## 6. Шпаргалка

| Задача | Команда |
|---|---|
| Где я сейчас? | `git branch` |
| Есть ли мои несохранённые правки? | `git status` |
| Скачать обновления с GitHub | `git fetch origin` |
| Перейти на новую ветку | `git checkout arena/01a01e47-ros2-ws` |
| Вернуться на старый код | `git checkout main` |
| Что изменилось в файле | `git diff main -- путь/к/файлу` |
| Список изменённых файлов | `git diff --stat main` |
| Пересобрать проект начисто | `./rebuild.sh` |
| Дособрать без очистки | `./rebuild.sh --keep` |
| Собрать только один пакет | `colcon build --packages-select robot_navigation` |

## 7. Частые затруднения

**`git checkout` ругается: `Your local changes would be overwritten`**
У вас есть несохранённые правки в тех же файлах. Уберите их «в карман»
командой `git stash`, затем повторите `checkout`.

**`colcon build` падает с `Package 'nav2_...' not found`**
Не выполнен шаг 5 — не установлены пакеты Nav2 через `apt`.

**Узел падает с `PackageNotFoundError: No package metadata was found for ...`**
Смешаны два режима сборки colcon. Выполните `./rebuild.sh` — он всё
очистит и соберёт заново.

**`ros2 launch` пишет `package not found`**
Не выполнена команда `source ~/ros2_ws/install/setup.bash` в этом терминале.

**Собралось, но старое поведение не изменилось**
Собирали не в той папке. `colcon build` запускается строго из `~/ros2_ws`,
а не из `~/ros2_ws/src`.

**Хочу посмотреть код, не трогая робота**
Откройте ссылку из раздела 2 в браузере на любом устройстве.
